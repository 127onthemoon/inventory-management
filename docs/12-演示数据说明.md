# 12 演示数据说明

> 2026-11-16：运行库 `inventory_db` 中原有压测（PERF-*）与冒烟测试（SMOKE*）留下的 8 个压测商品、约 2.3 万条流水已清理，换成一套可复现的演示数据。
> **测试库 `inventory_test` 与 `perf/results/` 原始压测结果未做任何改动**，测试报告与性能报告中的数据保持不变。

## 1. 备份

清理前用 mysqldump 备份了完整的 `inventory_db`：`backup/inventory_db-before-demo-reset-20261116-160351.sql.gz`（`--single-transaction`，含 8 个 PERF 商品、23,593 条流水）。
`backup/` 目录不进入发布包。恢复方法：`gunzip -c backup/<文件>.sql.gz | mysql -uinventory -p inventory_db`。

## 2. 生成方式：`scripts/seed-demo.sh`

```bash
scripts/seed-demo.sh            # 应用需在运行；默认先备份，再重建演示数据并核对
NO_BACKUP=1 scripts/seed-demo.sh
```

| 步骤 | 做法 |
|---|---|
| 1 备份 | mysqldump → `backup/inventory_db-时间戳.sql.gz` |
| 2 重建 | 清空 7 张业务表，重新执行 `src/main/resources/db/data.sql`（2 个账号、4 个分类、3 个供应商、8 个商品及期初入库单/流水） |
| 3 基础资料 | `scripts/seed_demo.py` 登录管理后台，**通过表单**新增 2 个分类（劳保用品、包装耗材）、2 个供应商、12 个商品 |
| 4 出入库 | **通过 REST 接口** `POST /api/stock/in`、`/api/stock/out`（HTTP Basic、带幂等号）办理 238 张单据：入库 47 张、出库 191 张；出库约 70% 由 operator、30% 由 admin 办理。库存、单据、流水都由 `StockService` 在同一事务里写入 |
| 5 回填日期 | 把每张单据及其流水的 `created_at`，连同单号里的时间部分，改为计划的日期（过去 13 天 ~ 今天，每天 08:30–17:30）。**只改时间，不改数量**，时间顺序与 id 顺序一致，所以流水链和“库存 = 期初 + Σ入库 − Σ出库”不受影响 |
| 6 核对 | 执行 `scripts/check-consistency.sql`，任何商品 MISMATCH 或流水链断裂、负库存、重复幂等号都让脚本返回非 0 |

模拟逻辑用固定随机种子（20261116），每次生成的数量完全相同，只有日期跟着运行当天走。脚本会先在本地模拟出预计库存，提交完再和系统实际库存逐个比对（输出“全部一致”）。
