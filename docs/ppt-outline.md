### 第 8 页　核心难点：为什么会超卖（反例实验）
* “读库存 → Java 计算 → 写回”存在时间窗口
* 实测：100 线程抢 50 件，**100 个都“卖出成功”，库存只减少 3**
* 对照：原子条件更新成功恰为 50、库存 0
* 来源：`docs/test-results/concurrency-test-output.txt` 中 `[EXPERIMENT]` 两行

### 第 9 页　解决方案：原子条件更新 + 事务 + 唯一约束
* `UPDATE product SET stock = stock - ? WHERE id = ? AND stock >= ?`，影响 0 行 = 库存不足
* 事务内四步：扣减 → FOR UPDATE 当前读 → 写单据 → 写流水；任一步失败整体回滚
* 幂等三层：按钮禁用 → requestId 快速路径 → 唯一约束冲突回滚
* 死锁重试 ≤ 3 次（事务外）
* 图：`03-架构设计.md` 第 5 节时序图；代码：`StockTxService.doStockOut`
