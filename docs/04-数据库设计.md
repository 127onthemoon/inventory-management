# 数据库设计

* 数据库：MySQL 8.4.13，InnoDB 引擎，字符集 utf8mb4 / utf8mb4_unicode_ci，时区 +08:00
* 库名：`inventory_db`（运行）、`inventory_test`（自动化测试）；应用账号由环境变量 `DB_USER` / `DB_PASSWORD` 配置（勿把真实口令写入仓库）
* 建表脚本：`src/main/resources/db/schema.sql`；初始数据：`src/main/resources/db/data.sql`（应用启动自动执行，可重复执行）
* Hibernate 设置为 `ddl-auto=validate`：表结构以 SQL 脚本为准，启动时校验实体映射与表结构一致

## 1. E-R 关系

```
category 1 ──── N product N ──── 0..1 supplier
                    │ 1
     ┌──────────────┼──────────────┐
     N              N              N
stock_in_order  stock_out_order  stock_flow
     │ N                              ▲
     └── 0..1 supplier                │ ref_order_no 关联 in/out 单据号（一单一条流水）
sys_user（独立；单据/流水记录 operator 用户名）
```

## 3. 约束在并发控制中的作用

| 约束 | 作用 |
|---|---|
| `ck_product_stock_non_negative CHECK (stock >= 0)` | 最后防线：即使有人绕过应用直接写 SQL，也不可能出现负库存（测试 `databaseCheckConstraint` 验证） |
| `uk_out_request_id / uk_in_request_id` | 幂等：同一请求号只能成功插入一次；冲突使整个事务回滚，撤销已执行的扣减 |
| `uk_out_order_no / uk_in_order_no` | 单据号全局唯一 |
| `uk_flow_ref_order` | 一张单据只对应一条流水，防止重复记账 |
| 外键 | 保证单据/流水引用的商品、供应商真实存在；有引用时禁止删除 |

## 4. 一致性不变式（可用 `scripts/check-consistency.sql` 核对）

1. `product.stock = Σ(IN 流水数量) − Σ(OUT 流水数量)`
2. `product.stock = Σ(入库单数量) − Σ(出库单数量)`
3. `流水条数 = 入库单数 + 出库单数`
4. 同一商品按 id 排序：`flow[i].before_stock = flow[i-1].after_stock`，且 `after = before ± quantity`
5. 不存在负库存，不存在重复的 request_id / ref_order_no

为满足不变式 1~3，`data.sql` 中的商品期初库存也以“期初入库单 + 入库流水”的形式写入。

## 5. 索引设计

| 表 | 索引 | 用途 |
|---|---|---|
| product | uk_product_code、idx_product_category、idx_product_supplier | 编码查重、按分类筛选 |
| stock_in/out_order | uk_*_request_id、uk_*_order_no、idx_*_product、idx_*_created | 幂等查询、按商品筛选、按日期统计 |
| stock_flow | idx_flow_product (product_id, id)、idx_flow_created、uk_flow_ref_order | 流水链核对、最近流水 |
