# 高并发库存管理系统 —— 需求规格说明书（SRS）

> 文档版本：v1.0　｜　对应流程：第 1 步「需求分析」+ 第 2 步「规格设计」
> 编写方式：AI 编程助手（Grok Bot）根据课程方案自主分解，所有验收标准均可由自动化测试或压测脚本验证。

## 1. 项目背景与目标

本项目是《Java语言及网络编程》课程结课作业（AI 工程化实践方向），实现一个用于管理**商品、分类、供应商、入库、出库与库存流水**的单体 Web 系统。
核心技术亮点是：**在高并发出库/入库场景下，依靠数据库原子条件更新 + 事务 + 唯一约束，保证不超卖、不出现负库存、不重复扣减，且库存与流水始终一致**。

非目标：不投入生产；不做分布式、微服务、缓存（Redis）、消息队列、前端框架（Vue/React）。

## 2. 用户角色

| 角色 | 标识 | 说明 |
|---|---|---|
| 管理员 | `ADMIN` | 拥有全部权限：基础资料（商品/分类/供应商）增删改、用户管理、入库、出库、查看统计与流水 |
| 操作员 | `OPERATOR` | 日常作业：查看基础资料、办理入库与出库、查看流水与统计；**不能**增删改基础资料，**不能**访问用户管理 |

默认账号（由 `data.sql` 初始化）：`admin / admin123`（管理员）、`operator / operator123`（操作员）。

## 3. 功能需求

| 编号 | 模块 | 需求描述 | 角色 |
|---|---|---|---|
| F-01 | 登录 | 表单登录、退出；未登录访问任何业务页面跳转登录页；密码 BCrypt 加密存储；被禁用用户不能登录 | 全部 |
| F-02 | 商品管理 | 商品列表（按编码/名称关键字、分类筛选，分页）；新增、编辑、删除；字段：商品编码（唯一）、名称、分类、供应商、单位、单价、当前库存（只读）、预警阈值、状态 | 查：全部；增删改：ADMIN |
| F-03 | 分类管理 | 分类增删改查；分类名唯一；分类下有商品时禁止删除 | 查：全部；增删改：ADMIN |
| F-04 | 供应商管理 | 供应商增删改查：名称（唯一）、联系人、电话、邮箱、地址、备注；被商品/入库单引用时禁止删除 | 查：全部；增删改：ADMIN |
| F-05 | 入库管理 | 创建入库单（商品、供应商、数量、单价、备注），增加库存，记录操作人和时间；入库单列表 | 全部 |
| F-06 | 出库管理 | 创建出库单（商品、数量、去向/客户、备注），**检查并扣减库存，库存不足时拒绝**；出库单列表 | 全部 |
| F-07 | 库存流水 | 每次库存变动写一条流水：商品、变动类型（IN/OUT）、数量、变动前库存、变动后库存、关联单据号、操作人、时间；可按商品、类型筛选 | 全部 |

| F-09 | 用户管理 | 用户列表、新增用户、修改姓名/角色、重置密码、启用/禁用；不能禁用自己 | ADMIN |
| F-10 | 一致性核对 | 提供核对接口/页面：每个商品 `当前库存 == Σ入库流水 − Σ出库流水`，并核对流水链（每条 before = 上一条 after） | 全部（只读） |
| F-11 | REST 接口 | 提供 JSON 接口用于压测与演示：`POST /api/stock/out`、`POST /api/stock/in`、`GET /api/products/{id}`、`GET /api/stock/consistency` 等 | 登录用户 |

## 4. 业务规则（Business Rules）

| 编号 | 规则 |
|---|---|
| BR-01 | 商品库存**只能**通过入库单/出库单变更；商品编辑表单不允许直接修改库存 |
| BR-02 | 出/入库数量必须为正整数（1 ~ 1,000,000） |
| BR-03 | 出库时若 `库存 < 出库数量`，拒绝出库，返回「库存不足」，**不产生任何单据和流水** |
| BR-04 | 库存永远不为负（应用层条件更新 + 数据库 `CHECK (stock >= 0)` 双重保证） |
| BR-05 | 每张单据携带一个请求幂等号 `request_id`（页面打开表单时生成 UUID，接口由调用方传入）；同一幂等号**只会生效一次**，重复提交返回第一次的处理结果（标记 `duplicate=true`） |
| BR-06 | 单据号 `order_no` 全局唯一，格式 `IN/OUT + yyyyMMddHHmmssSSS + 4位随机数` |
| BR-07 | 「写单据 + 改库存 + 写流水」在**同一个数据库事务**中完成，任一步失败整体回滚 |
| BR-08 | 停用（status=0）的商品不能办理入库/出库 |
| BR-09 | 已有库存流水的商品不能物理删除（可改为停用）；有商品的分类、被引用的供应商不能删除 |
| BR-10 | 不允许用 `synchronized`/JVM 锁或「读库存→内存计算→写回」实现扣减 |

## 5. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NF-01 | 并发正确性 | 初始库存 50，100 个并发请求各出库 1：成功恰好 50，最终库存 0，无负库存；500 并发抢 50 同样成立 |
| NF-02 | 一致性 | 任意时刻 `product.stock = Σ IN − Σ OUT`（基于流水），流水条数 = 成功单据数 |
| NF-03 | 幂等 | 同一 `request_id` 并发/重复提交 N 次，只扣减一次、只有一张单据、一条流水 |
| NF-04 | 性能（课程级目标） | 本机单实例下，出库接口在 100~500 并发下系统错误率 0%（业务拒绝不计为系统错误），并记录吞吐量与 P95 响应时间 |
| NF-05 | 安全 | 密码 BCrypt；表单 CSRF 防护；基于角色的 URL 与方法级权限；SQL 一律参数化（JPA/命名参数） |
| NF-06 | 可用性 | 统一美观的管理后台风格，所有页面无模板错误；表单有校验提示；提交按钮防连点 |
| NF-07 | 可维护性 | 分层清晰（Controller / Service / Repository / Entity），并发控制代码有详细中文注释 |
| NF-08 | 可复现 | 提供 schema.sql / data.sql、启动脚本、JMeter 脚本与运行脚本、原始结果文件 |
