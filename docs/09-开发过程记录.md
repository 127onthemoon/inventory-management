## 2. 问题与解决

| 编号 | 现象 | 原因分析 | 解决办法 |
|---|---|---|---|
| E-1 | `apt-get update` 返回 500 / HTTPS 握手失败，无法用 apt 安装 openjdk、maven、mysql | 云端机器访问 Debian 软件源受限（curl 直接访问同一地址却正常） | 改为下载官方二进制包：Maven（dlcdn.apache.org）、JMeter（dlcdn.apache.org）、MySQL 8.4.13 Linux Generic（cdn.mysql.com）；JDK 使用已存在的 Temurin 21 tarball。未能使用 apt，但**仍使用了真实 MySQL 8**，无需 MariaDB 替代 |
| E-2 | `mysqld` 启动报缺少 `libaio.so.1`；`mysql` 客户端缺少 `libncurses.so.6` | Debian 13 中 libaio 改名为 `libaio1t64`（库文件 `libaio.so.1t64`）；系统只有 ncursesw | 用 curl 从 Debian 源下载 `libaio1t64`、`libncurses6` 的 .deb 并 `dpkg -i`；为 `libaio.so.1t64` 建立 `libaio.so.1` 软链接 |
| E-3 | Maven 仓库访问速度 | 实测 Maven Central 响应约 40 ms | 无需切换阿里云镜像，依赖 16 秒下载完成 |
| E-4 | 机器时区为 Asia/Shanghai（UTC+8） | — | 应用 JVM、JDBC `serverTimezone`、MySQL `default-time-zone` 统一为 +08:00，避免时间错位 |
| D-1 | 首次启动失败：`Schema-validation: wrong column type encountered in column [status] in table [product]; found [tinyint], but expecting [integer]` | `ddl-auto=validate` 严格校验：实体为 Integer，表为 TINYINT | `schema.sql` 中 `product.status` 改为 INT，重建开发库后启动成功。说明 validate 模式能及早发现实体与脚本不一致 |
| D-2 | 设计评审发现：`GlobalModelAdvice` 若作用于所有控制器，每个 REST 请求都会多一次用户查询 | `@ControllerAdvice` 默认对所有控制器生效，`@ModelAttribute` 方法也会在 @RestController 上执行 | 页面控制器与接口控制器分包（`controller.web` / `controller.api`），Advice 只作用于 `controller.web` |
| D-3 | 单据号最初用“毫秒时间戳 + 4 位随机数”，在单元测试设计时意识到同一毫秒大量生成时可能碰撞 | 随机数生日碰撞 | 改为 `AtomicInteger` 循环序号（无锁 CAS），并保留唯一约束 + 冲突换号重试；`OrderNoGeneratorTest` 验证 8 线程 20000 个无重复 |
| T-1 | `databaseCheckConstraint` 测试失败：期望 `DataIntegrityViolationException`，实际为 `UncategorizedSQLException ... error code [3819]; Check constraint 'ck_product_stock_non_negative' is violated` | Spring 的 MySQL 错误码映射表未收录 MySQL 8 新增的 CHECK 约束错误码 3819 | 测试改为断言 `DataAccessException` 且消息包含约束名。生产代码中扣减本就有 `stock >= ?` 条件，CHECK 只是兜底 |
| P-1 | 压测若用 HTTP Basic，每个请求都要做一次 BCrypt（约数十毫秒 CPU），结果会主要反映密码校验开销 | BCrypt 设计上就是慢哈希 | JMeter 每线程只登录一次（提取 `_csrf` → 表单登录），之后复用会话 Cookie；登录请求在统计中单列 |
| P-2 | 想用一个 jmx 通过参数开关同步定时器，发现 JMeter Synchronizing Timer 的 `groupSize=0` 表示“全部线程”，无法用 0 关闭 | JMeter 语义 | 拆成两个脚本：`stock-out-burst.jmx`（含同步定时器）与 `stock-load.jmx`（无同步定时器，可混合入库） |
| P-3 | 混合场景中“出库分支”“入库分支”两个 If 控制器各自调用 `__Random`，可能同一次循环两个都执行或都不执行 | 两次独立随机 | 第一个 If 用 `__Random(1,100,r)` 把随机数存入变量 `r`，第二个 If 复用 `${r}`，保证每次循环恰好执行一个分支 |
| P-4 | 首次试跑 burst100（无预热）出库平均响应 886 ms | 应用刚启动，JIT 未预热、连接池未扩容 | 增加 warmup 场景（结果单独保存、不计入分析），之后重新执行全部场景；试跑结果已删除，试跑使用的商品（id=9）仍保留在库中且一致性核对为 OK |
| P-5 | 重启应用时 `app.log` 被覆盖，压测期间的应用日志丢失 | `start.sh` 用 `>` 重定向 | `start.sh` 改为先把旧日志归档到 `logs/` 再启动 |
| U-1 | 截图发现仪表盘“今日入库/出库”数字很大时换行 | 卡片宽度不足 | `.stat-value` 字号 24→22px 并 `white-space: nowrap` |
| U-2 | 本机没有 Selenium / Playwright，无法直接截图带登录态的页面 | — | 用 Chrome 无头模式 + DevTools 协议，Java 11 自带 `java.net.http.WebSocket` 写了一个 70 行的小工具 `scripts/screenshot/Shot.java`：先 curl 登录拿会话 Cookie，再注入 Chrome 截图 |

## 3. 关键设计决策记录

见 `02-开发计划.md` 中的 ADR 摘要（D-01 ~ D-07）。补充两点：

* **事务内操作顺序选择“先扣减、后写单据”**：最初考虑“先插单据占用幂等号再扣减”，但那样单据插入时还不知道变动前后库存，需要再 UPDATE 一次单据；
  改为先扣减后，相同幂等号的并发请求会先在商品行锁上排队，后到者插入单据时触发唯一键冲突、整个事务回滚，同样不会重复扣减，而且所有事务的加锁顺序一致（都先锁商品行），死锁更少。
* **不引入 Swagger/OpenAPI**：用户最初的口头需求提到 Swagger，但随后提供的正式方案明确要求“不为技术展示而无意义增加依赖”，以正式方案为准；REST 接口在 README 中以表格和 curl 示例说明。
